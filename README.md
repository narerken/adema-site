# мир Адемы

Приватный сайт-сюрприз для Адемы: фотки (с избранным и загрузкой пачкой),
музыка по настроению (с избранным, автопереходом и перемешкой), записки
«open when...» (с сохранением любимых), чек-лист дня со стриком и
кнопка-сюрприз на главной. Фронтенд — React + Vite + Tailwind + Framer
Motion. Бэкенд — Go (без внешних зависимостей, хранит всё в JSON-файле +
папках с загруженными файлами, так что деплоить можно куда угодно).

## Структура

```
adema/
  frontend/   # React-приложение
  backend/    # Go API сервер
  docker-compose.yml
```

## 1. Запуск локально (для проверки)

### Бэкенд
```bash
cd backend
go run .
```
По умолчанию поднимется на `http://localhost:8080`.
Коды доступа по умолчанию: `owner123` (ты) и `adema123` (Адема) —
**обязательно смени их** через переменные окружения:
```bash
OWNER_PASSCODE=мой_секретный_код ADEMA_PASSCODE=код_адемы go run .
```

### Фронтенд
```bash
cd frontend
npm install
cp .env.example .env.local   # и пропиши VITE_API_URL=http://localhost:8080
npm run dev
```
Открой `http://localhost:5173`.

## 2. Что можно (и нужно) настроить под себя

- **Записки** — `backend/notes_data.go`. Добавляй/меняй тексты в каждой
  категории (`sad`, `miss`, `motivation`, `sleep`, `smile`). Они не
  повторяются, пока не покажутся все, потом цикл начинается заново.
- **Чек-лист дня** — `backend/tasks_data.go`. Пул задачек, из которого каждый
  день собирается список (`itemsPerDay` штук). Чем длиннее пул, тем позже
  задачки начнут повторяться.
- **Настроения в музыке** — `backend/music.go` (`validMoods`) и
  `frontend/src/pages/Music.jsx` (`moodMeta`), если захочешь другие категории.
- **Фоновая музыка** — положи свой трек файлом
  `frontend/public/background-music.mp3` (именно с таким именем) и
  пересобери сайт. Кнопка вкл/выкл в шапке сайта заработает сама; пока
  файла нет, кнопка просто неактивна.
- **Цвета/дизайн** — `frontend/src/index.css` (переменные `--cream`, `--pink`
  и т.д.). Иллюстрации — все оригинальные, нарисованы с нуля специально для
  сайта: `Doodles.jsx` (бабочки, цветы), `BlobCats.jsx` (котики) и
  `Icons.jsx` (простые линейные иконки вместо эмодзи). Всё можно смело менять.

После любых правок в Go-файлах бэкенд нужно перезапустить.

## 3. Как всё устроено внутри

- **Фото**: общий альбом грузишь только ты (роль `owner`), приватный альбом
  грузит только Адема (роль `adema`). Оба альбома видят оба (это же ваш общий
  сайт), но загружать в «не свой» альбом нельзя.
- **Музыка**: оба могут загружать треки в любое настроение. Можно
  перемешивать плейлист и фильтровать только избранные треки, следующий трек
  включается автоматически.
- **Избранное**: звёздочка на фото, треках и записках — сохранённое видно в
  отдельной вкладке/списке.
- **Чек-лист дня**: считает стрик (сколько дней подряд выполнен список
  полностью) и лучший стрик за всё время — виден на главной и на странице
  чек-листа.
- **Кнопка-сюрприз** на главной — просто поднимает настроение, без бэкенда.
- **Авторизация**: простая — два секретных кода, без email/паролей. Токен
  сохраняется в браузере.
- **Данные** хранятся в `backend/data/db.json`, файлы — в
  `backend/uploads/photos` и `backend/uploads/music`. Это и есть твоя "база
  данных" — не удаляй эти папки на сервере, иначе всё потеряется. Полезно
  иногда скачивать их как бэкап.

## 4. Деплой (чтобы Адема могла открыть сайт из любого места)

### Вариант А — свой VPS + Docker (рекомендую, самый надёжный для файлов)

Подойдёт самый дешёвый VPS (например, от 3-5$/мес: Timeweb, Selectel,
Hetzner, DigitalOcean — выбирай то, что тебе удобнее оплатить).

1. Установи Docker и Docker Compose на сервере.
2. Скопируй туда папку `adema/` (например, через `git` или `scp`).
3. `cp .env.example .env` и впиши свои секретные коды доступа.
4. `docker compose up -d --build`
5. Сайт будет доступен на 80 порту сервера (`http://IP_СЕРВЕРА`). Чтобы был
   красивый домен и https — направь домен на IP сервера и поставь перед
   контейнером Caddy/Nginx с автоматическим SSL (или используй Cloudflare).

Все фото/музыка сохраняются в Docker volume — переживут перезапуск
контейнеров.

### Вариант Б — без своего сервера (Railway + Vercel/Netlify)

1. **Бэкенд на Railway** (или Render/Fly.io):
   - Создай новый проект из папки `backend/` (там есть `Dockerfile`).
   - Подключи **persistent volume**, смонтируй в `/app/uploads` и
     `/app/data` (иначе фото будут исчезать при каждом деплое!).
   - Пропиши переменные окружения `OWNER_PASSCODE`, `ADEMA_PASSCODE`,
     `ALLOWED_ORIGIN` (домен фронтенда, например `https://adema.vercel.app`).
   - Запомни публичный URL бэкенда (например `https://adema-backend.up.railway.app`).
2. **Фронтенд на Vercel или Netlify**:
   - Импортируй папку `frontend/`.
   - Build command: `npm run build`, output: `dist`.
   - Переменная окружения `VITE_API_URL` = URL бэкенда из шага выше.
3. Открой сайт по ссылке с Vercel/Netlify — готово.

## 5. Два секретных кода

У владельца (тебя) и у Адемы — разные коды входа, чтобы сайт понимал, кто
смотрит, и показывал нужные права на загрузку. Код передай Адеме отдельно
(например, в сообщении или на самой первой открытке/подарке 🖤).
